# 041 — 内存流量优化的长期跟踪（032 跟进）

- 状态：planned（长期项，非当前承诺）
- 优先级：P3
- 依赖：032（报告/预算/调优已交付）
- 预估规模：周级（含上游级改造）

## 1. 背景与现状

032 已完成：强/弱扩展与内存报告（`scripts/perf-scaling.sh`）、百万
单元能力与预算曲线（1M 单元 2.0 GB 串行 / ~0.61 GB/rank @4）、
`nSubCycles 8` −26%（1.35×，守恒达标）、容差/修正器调优阴性、GAMG
排除、推荐生产配置。遗留结论：并行效率 55k→1M 由 49% 降至 36%，
**带宽/通信受限是系统性的**，repo 侧无有效杠杆。

## 2. 目标（若启动）

1. 量化：把每步时间细分到求解器项（压力/α/能量/通信/I/O），确认
   带宽受限的占比与通信占比（perf-scaling 报告扩展）；
2. 候选方向逐一实测：消息聚合（OpenFOAM 内部）、定制压力求解器
   （更低内存流量）、场 I/O 压缩/二进制、`nSubCycles`/分解策略组合；
3. 至少一个方向给出 ≥10% 实测收益且守恒/精度不劣化；否则维持
   文档结论并关闭。

非目标：修改上游 OpenFOAM；牺牲守恒/精度的加速。

## 3. 技术方案（候选）

- **A. 细分计时**：OpenFOAM `solverPerformance`/`ExecutionTime` 已有
  分项；扩展 `perf-scaling.sh` 汇总输出（求解器项 + 通信 + I/O）；
- **B. 场 I/O**：验证/测试用例改 `writeFormat binary` 或减少写出
  字段（不改契约 case 的验收口径）；
- **C. 分解/子循环组合**：scotch vs hierarchical、`nSubCycles` ×
  `maxCo` 矩阵（在守恒门槛内）；
- **D. 上游级**（仅跟踪）：定制压力求解器、聚合通信。

## 4. 验收标准（DoD，若启动）

- 每步分解报告（A）落地；
- ≥1 方向 ≥10% 收益且 22+ 用例与守恒不劣化；或明确的关闭结论；
- 文档与 README 性能章节同步。

## 5. 风险与缓解

|------|------|

| 优化影响精度 | 精度/守恒为门槛（不放宽阈值） |
