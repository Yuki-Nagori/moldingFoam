# 007 — 黏性生热（能量方程剪切耗散项）

- 状态：done（2026-09-10。验收：解析 Couette 对拍相对误差 4.1e-4；
  契约 case 开启后全项 PASS；`xmake run test` 全部 PASS）
- 优先级：P0（注塑剪切生热对温度场影响一阶）
- 依赖：建议在 001（潜热）/006（周期完备化）之后
- 预估规模：2–4 天

## 1. 背景与现状

`compressibleVoF::thermophysicalPredictor()`（本库在 `moldingFoam`
覆写）的能量方程包含瞬变、对流、压力功与动能项，但**没有黏性耗散
（剪切生热）项**（已核实上游实现与本地覆写）。

注塑工况：

- 剪切速率 1e3–1e5 1/s（薄壁/浇口可达 1e6）；
- Cross-WLF 剪切应力 1e4–1e6 Pa；
- 剪切生热功率密度 `τ:∇u` 常使局部温度升高 10–50 K；
- 影响充填压降、冻结层厚度、潜热释放时刻、短射与烧焦。

因此缺少该项会系统性低估熔体温度、高估黏度/压降，是注塑物理的
一阶缺口。

## 2. 目标与非目标

### 目标
1. 在能量预报器加入与动量方程**同一应力定义**的黏性耗散源；
2. 源项为正定、数值稳定（必要时做有界/半隐式处理）；
3. 可字典开关，缺省关闭以保证既有 case 回归（新 case 可开启）；
4. 解析算例对拍（Couette 剪切层稳态/瞬态平衡温度）；
5. 契约 case 开启后稳定，温升合理。

### 非目标
- 黏弹性/法向应力（GNF 范围之外）；
- 壁面滑移（另立任务）；
- 压力依赖的耗散修正（超出 GNF）。

## 3. 技术方案

### 3.1 物理与离散形式

不可压缩内能方程的黏性耗散源：

```
Φ = τ : ∇u = 2·η·dev(symm(∇u)) : ∇u
```

- `η` 为动力黏度，取与动量方程**同一** CrossWlf 模型、同一应变率
  定义 `γ̇ = √2·mag(symm(∇u))`，逐单元经
  `CrossWlf::eta(coeffs, p, T, γ̇)` 求值（重载避免逐单元重读字典）；
- 动量方程的有效黏性应力为
  `η[∇u + (∇u)ᵀ − (2/3)tr(∇u)I] = 2η·dev(symm(∇u))`；耗散必须用这个
  **对称**应力。注意不要写成 `dev2(T(∇u)) && ∇u`：该组合在简单剪切
  下恒为零（已被 Couette 解析验证捕获）；
- 量纲 [W/m³]；显式正源直接加入能量矩阵的积分源项；
- 若时间步较大导致过冲，可改为按 `Cv·ΔT` 限制的有界源（参照潜热峰
  的处理），当前解析与契约验证均无需。

### 3.2 与现有能量项的耦合

- 现有方程已含压力功与动能项；耗散项与其量级需在解析算例中核对
  符号与系数（τ 的 dev2 修正、压缩项）；
- 与潜热表观热容共存的稳定性：二者都是温度的非线性源，必要时增加
  能量子迭代（见 001 风险条目）。

### 3.3 开关与契约

- `constant/moldingDict` 新增可选 `viscousDissipation`（bool，缺省
  false = 旧行为；契约 case 验证时可开启）；
- 或作为 `fvModels` 源模型实现（自注册 `fvModel`），但为保持零上游
  改动与简单性，先做求解器内显式源。

## 4. 工作拆解

1. 核对 OF-14 动量方程应力形式（`momentumTransport.divDevTau`）与
   `nuEff` 边界接口；
2. `moldingFoam::thermophysicalPredictor` 加入耗散源与开关；
3. 解析算例：
   - **瞬态**：绝热（无传导）常剪切，`dT/dt = μγ̇²/(ρCp)`；
   - **稳态**：两壁温差/剪切平衡，温度抛物分布；
   - 用窄缝 1D case 或 function object 输出对拍；
4. 契约 case 对比（开/关）：温度场、顶出时刻、质量守恒回归；
5. README §6/§7、契约日志 v1.5、本文件状态更新。

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 显式正源在细网格/大剪切下刚性过冲 | 有界源（按可承受 ΔT 限制）或能量子迭代；必要时局部隐式 |
| 应力符号/系数错误 | 用解析 Couette 算例逐项核对；与动量方程共用 `nuEff` 与 `dev2` |
| 与潜热/模温耦合的稳定性 | 先单独验证，再全周期回归；能量子迭代提供兜底 |
| `nuEff` 与 CrossWlf 的一致性 | 直接读取 `momentumTransport.nuEff()`，不重复实现 |
