# 068：流道非线性收敛诊断与重复求解优化

- 状态：planned
- 优先级：P2
- 依赖：058 / 062 / 063
- 来源：2026-09-15 整体复核；承接 063 以外的明确剩余项

## 背景与现状

`solveTree()` 使用 500 次上限与 1e-14*Q 的停止条件，到上限静默返回。
各 gateFlow/gateTemperature/pressureDrop 查询重复求整个网络；目前没有
证明这些重复计算在代表性多浇口模型中的成本占比。

## 目标与非目标

先使每次网络求解能证明收敛，再按测量结果缓存一致输入下的全部叶子结果。
不预先承诺加速比例，不改动 062 的逐浇口指定流量语义。

## 工作拆解与涉及文件

1. `moldingRunnerNetwork`：输出迭代数、流量守恒及路径压力残差；不收敛
   应明确告警/拒绝，阈值由有量纲绝对项与相对项组成。
2. 构造不对称树、强剪切变稀、阀关闭、低流量和不等温的模型级对照。
3. 在固定 Q/t/配置版本下缓存叶子流量/温度/压降，失效键包含全部影响
   网络的状态；不可只按 timeIndex 缓存，PIMPLE 中 Q 会变。
4. 与 062 的拷贝构造、Function1 生命周期及超配规则对齐；按同会话记录
   迭代次数和墙钟，验证缓存开关不改物理结果。

## 验收标准

收敛结果通过独立守恒/路径压降检查；强制低迭代上限能触发失败断言。
缓存开关在相同输入逐点一致，改变 Q/t/阀状态不返回旧结果。
本地只跑小网络模型与秒级基准，收益不足则保留阴性结论、不引入缓存。

共享 DoD 仍适用：构建无新增告警、相应最小测试及完整 CI/契约验收，记录
提交哈希与取证口径后再标 done。遵循 `../diagnostics.md`。

## 风险与缓解

默认容差过紧可能浪费迭代，但不能未量化就放宽。共享结果的所有权及
边界 clone() 必须明确，避免重演 062 的空项 PtrList 拷贝问题。
