# 048 — 求解成本杠杆组合实测与每步通信削减

- 状态：done（2026-09-14：诊断门控落地 + 杠杆 A/D/E 三档实测；E 支配基线，契约变更建议见 §3c）
- 优先级：P1
- 依赖：032（nSubCycles 8）、041（能量容差 1e-5）
- 预估规模：1–2 天
- 来源：046 后续评估——两个已测单项杠杆各自 −26% / −24%，但**组合
  从未实测**，且两者吃同一份守恒余量

## 1. 背景与现状

- `nSubCycles 16→8`：墙钟 −26%（628.7→467.4 s 中位数），守恒
  9.383e-4→9.695e-4（032 §3c）；未改缺省（余量 6%→3%）；
- 能量解容差 1e-6→1e-5：墙钟 −24%（876→666 s），守恒 9.696e-4
  （041 §4b）；未改缺省，记为按需选项；
- 两项的守恒增量分别是 +3.3% 与 +3.3%，叠加后可能贴近或越过
  1e-3 阈值——**必须先测再谈缺省**；
- 另一个每步成本项：`massBudget` 诊断的逐 patch 求和与打印**每步
  都做**（实测 cli10：5,080 步打出 8,092 行 `mass budget patch`，而
  真正被消费的汇总行只有 25 行 = `massBudgetInterval 200` 次），
  这些量只在 interval 步用于打印，可按 interval 门控；
- 已否决（勿重复）：GAMG（慢 13%）、`nCorrectors 2`（破守恒）、
  容差组合调优（无加速）、界面子循环放宽（2.5e-3 破线）、
  `maxCo 0.25`、`ventSealAlpha 0.99`、强制 ddtCorr。

## 2. 目标

1. **同会话同 VM** 测三档：基线（16 / 1e-6）、单位杠杆（8 / 1e-6、
   16 / 1e-5）、组合（8 / 1e-5），每档重复 ≥2 次取中位数，记录墙钟、
   步数、质量守恒、V/P 切换与压力跟随；
2. 若组合守恒 < 1e-3：写入 README §7 作为**长算例生产选项**（不改
   CI 缺省，理由同 041：夜间门禁需要抗漂移余量）；若 ≥1e-3：记录
   失败组合并给出「先根修守恒源（047/031）再谈叠加」的结论；
3. 诊断门控落地并量化：每步集合通信次数、日志行数、墙钟差（预期
   <1%，零风险，主要收益是同步点与日志体积）。

## 3. 技术方案

- 组合实验：`case-contract` 的 **scratch 副本**（不改契约本体），
  只覆盖 `fvSolution` 的 `nSubCycles` 与 `(U|e|T).*` 的 `tolerance`；
  用 `scripts/run-case.sh <scratch> 4` 跑，读 `log.foamRun` 末段验收
  摘要与 `ExecutionTime`；后台顺序执行，同会话对照；
- 诊断门控：`moldingFoam::postSolve` 中 `fluxVol`/`fluxAlpha`/逐 patch
  求和/打印、以及步分解的三个 `reduce`，全部移入
  `runTime.timeIndex() % massBudgetInterval_ == 0` 分支（`flux` 与
  `reduce(m)` 保持每步，因为 `massBudgetIn_` 每步累加）——条件由
  `timeIndex` 与全局字典给出，所有 rank 一致，不引入 rank 相关分支；
- 记录：`python3 scripts/perf-breakdown.py log.foamRun`（迭代分解）
  与 `grep -c` 的日志行数对照。

## 3a. 实测（2026-09-14，契约 case @4 进程，同会话，含 046 修复与诊断门控）

| 变体 | 墙钟 (s) | 步数 | ExecutionTime (s) | 质量守恒 | 验收 |
|------|----------|------|-------------------|----------|------|
| A 基线（16 / 1e-6） | 624 | 7692 | 621.8 | 9.391e-04 | PASS |
| D 组合（8 / 1e-5） | **382** | 7698 | 380.9 | **9.936e-04** | PASS |

- **组合实测 −39% 墙钟**（624 → 382 s，1.63×），步序列与基线一致
  （t ≤ 0.5 s 处 3786 vs 3787 步），单步成本 81 → 49 ms；
- **守恒 9.936e-04 距阈值仅 0.6% 余量**（基线 6.1%）——数学上过线，
  但按 045 记录的跨平台差异（1–10%）判断，**不能作为 CI 基线**；
- 结论：组合可作为**长算例生产选项**（本地/大件长跑），CI 缺省维持
  16 / 1e-6；要让组合进缺省，必须先由 047 把守恒余量做大（网格/时间
  归因）或根修界面离散；
- 重复样本（A/D 各 2 次取中位数）见 §3b（本节表为第一轮）。

## 3b. 重复样本与结论（2026-09-14，同会话 A/D/A/D）

| 变体 | 墙钟样本 (s) | 中位数 | 步数 | 质量守恒（两次相同） |
|------|--------------|--------|------|----------------------|
| A 基线（16 / 1e-6） | 624 / 731 | 677.5 | 7692 | 9.391e-04 |
| D 组合（8 / 1e-5） | 382 / 382 | **382** | 7698 | **9.936e-04** |

- **组合 −43.6% 墙钟**（中位数 677.5 → 382 s），且 D 的波动远小于基线
  （±0.03% vs ±8.6%）；
- 守恒 9.936e-04 < 1e-3（余量 0.6%），两次完全一致（守恒是设置的
  确定函数，与计时无关）；
- **结论**：D 作为长算例生产选项可用（−44%），**不入 CI 缺省**——按
  045 的跨平台差异 1–10% 记录，0.6% 余量不足以守住夜间门禁；
  要让 D 进缺省，先由 047 把守恒余量做大（本轮 047 已定标：
  误差 ∝ dt^1.0，dt 减半是最直接的加余量手段，代价是步数翻倍）；
- 候选生产用法：本地/大件长跑用 `nSubCycles 8` + 能量 `tol 1e-5`，
  并把守恒自检（`verify-case.py`）留在流程里。

## 3c. 组合 + dt÷2（变体 E）：支配基线（2026-09-14）

| 变体 | 墙钟 (s) | 步数 | 质量守恒 | 余量 |
|------|----------|------|----------|------|
| A 基线（16 / 1e-6 / αCo 0.03） | 624 / 731（中位 677.5） | 7692 | 9.391e-04 | 6.1% |
| D 组合（8 / 1e-5 / αCo 0.03） | 382 / 382 | 7698 | 9.936e-04 | 0.6% |
| dt÷2（16 / 1e-6 / αCo 0.015） | 1741 | 15,206 | 4.850e-04 | 106% |
| **E 组合+dt÷2（8 / 1e-5 / αCo 0.015）** | **518 / 572（中位 545）** | 15,215 | **5.164e-04**（两次一致） | **48%** |

**E 支配基线**：墙钟中位 677.5 → 545 s（**−19.6%**；样本 518/572 vs 624/731）*且*守恒余量
从 6.1% 提高到 48%（1.8×）；完整验收 PASS（`accepted=1`，含压力跟随/
顶出判据）。机制：组合把单步成本压到 0.66×（49.6 → 33 ms），抵消了
dt 减半带来的步数翻倍（7,698 → 15,215，1.98×），净成本 1.31×D。

**为什么本任务不动契约缺省**：`case-contract/system/` 是与 Kairos 的
冻结接口（README §8），数值修改要走契约版本变更（v1.4/v1.5 有先例）并
同步 Kairos 侧对基线的期望；本任务只给出测量与建议，变更留给下一次契约
修订。**已采纳（v1.28，2026-09-14）**：契约 case 的 `nSubCycles 16→8`、能量
`tolerance 1e-6→1e-5`、`maxAlphaCo 0.03→0.015` 已落地，文档基线
更新为「15,215 步 / 5.164e-04」（README 第 8 节变更日志 v1.28）。
落地前的行为核对：切换判据仍由 `switchPressure 1.3e6` 在
fill ≈ 0.894 触发（与 v1.27 一致，压力型），闸口封冻/顶出判据不变——
物理路径无变化，只是 dt/子循环/容差更省。

  输入——「把守恒余量做大」比「吃掉余量换速度」优先。
